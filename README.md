# VP-SMC-CVD «Тройное подтверждение»

Локальный детерминированный бот для анализа ETHUSDT Binance Spot.
Результат: LONG / SHORT / ПРОПУСК, семь проверок, ATR/новости/контекст,
Entry, SL, TP1/TP2, RR и размер позиции при известном депозите.

## Запуск Windows

Требуется Python 3.12+.

```powershell
cd E:\arigami
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
.\start.ps1
```

Открыть http://127.0.0.1:8765. Также можно запустить `start.ps1`.
Сервис слушает только loopback. Остановка в терминале: Ctrl+C.
Если сервис запущен фоновым процессом во время установки, его PID находится
в `.runtime/server.pid`; перед остановкой проверьте, что PID принадлежит `python -m bot`.
Автозапуск после перезагрузки не установлен.

CLI допускает воспроизведение исторических данных относительно `as_of`:

```powershell
python -m bot examples/synthetic-long.json
python -m bot examples/synthetic-long.json --json
.\.venv\Scripts\python -m unittest discover -s tests -v
```

**Пример полностью синтетический, не является рыночным сигналом.**
Live API разрешает вход только при `as_of` за последние 60 секунд. Старые снимки
можно просмотреть, но результат принудительно ПРОПУСК, без торговых уровней.
Для входа последняя закрытая свеча должна быть не старше 60 секунд относительно
`as_of` и в CLI, и в API; устаревшая свеча не мешает просмотру остальных показателей.

## Загрузка ETHUSDT

`start.ps1` поднимает отдельный локальный сборщик: он догружает агрегированные
сделки ETHUSDT Spot с начала текущей UTC-сессии из публичного Binance REST API, затем
непрерывно получает новые сделки через WebSocket. Сырые сделки хранятся только в
`private-data/ethusdt-live.sqlite3`. Повторный запуск не создаёт второй сборщик.

Проверить прогресс можно в `GET /api/live-status` или командой:

```powershell
.\.venv\Scripts\python -m bot.live --status
```

Пока загрузка текущей сессии не завершена, профиль объёма намеренно остаётся
`НЕТ ДАННЫХ`: частичный профиль не используется для решения.

Загрузчик работает **только с ETHUSDT Binance Spot, 15m**. Сохраняет
`private-data/ethusdt-15m.json` и исходный ответ `private-data/ethusdt-15m-raw.json`.
Загрузите первый файл через кнопку «Загрузить JSON» в интерфейсе.

OHLCV берётся из публичного `/fapi/v1/klines`; незакрытая свеча исключается.
CVD накапливает `2 × taker_buy_base_asset_volume − volume` без сброса внутри истории.
Это биржевая разбивка объёма по агрессору, а не оценка по цвету свечей.
VWAP сессии UTC: сумма quote volume / сумма base volume с полуночи.
ATR движок рассчитывает из закрытых свечей. Профиль объёма по цене, OB/FVG,
календарь, порог низкого ATR, депозит и позиция не выдумываются и остаются отсутствующими.
При недоступности API (в том числе HTTP 451) загрузчик сообщает ошибку;
ранее сохранённый файл не подменяется новым временем.

В интерфейсе нажмите **«Обновить ETHUSDT»**: вручную загружать JSON для
обычного анализа больше не нужно. Кнопка получает только закрытые 15m свечи,
строит VWAP, CVD, ATR и после готовности сборщика — Session Volume Profile,
HVN/LVN и механически подтверждённые OB/FVG. Она не открывает позиции и не
передаёт бирже ключи или ордера.

## Исторический бэктест ETHUSDT

```powershell
python -m bot.history --start 2026-09-01 --end 2026-09-29
python -m bot.backtest --start 2026-09-01 --end 2026-09-29 --calendar strict
python -m bot.backtest --start 2026-09-01 --end 2026-09-29 --calendar research_bypass
```

История скачивается из архивов Binance: агрегированные сделки создают профиль
объёма по фактическим ценам, а 1m OHLCV моделирует исполнение. SHA-256 каждого
архива, число сделок и расхождение объёма сделок со свечами сохраняются в
`private-data/backtest/manifest.json`. При расхождении выше 0.5% день
отклоняется. Строгий режим не запускает сделки без проверенного исторического
экономического календаря. `research_bypass` нужен для исследования механики и
не подтверждает готовность стратегии к торговле.

## API

`GET /health` — проверка состояния. `POST /api/analyze` — JSON с данными;
ответ содержит `analysis` и текстовый `report` на русском языке.
Обязателен `Content-Type: application/json`. Максимум 2 МБ.
Пустые данные дают ПРОПУСК, некорректный JSON — HTTP 400.

## Контракт данных

Полный образец: `examples/synthetic-long.json`.
Все цены и объёмы — конечные JSON-числа, время — ISO 8601 с часовым поясом.
Данные одного инструмента и биржи должны относиться к одному срезу рынка.
Система доверяет указанному источнику: подпись и независимая проверка поставщика не реализованы.

| Поле | Требования |
|---|---|
| `symbol`, `exchange`, `source` | Инструмент, площадка, источник данных |
| `timeframe_minutes`, `as_of` | 15 или 30; время анализа |
| `candles` | Минимум 35 последовательных закрытых OHLCV-свечей; `open, high, low, close, volume, close_time, closed` |
| `profile` | `type`: `session` для 15m, `fixed_range` для 30m; `start`, `end`, `source`; зоны `poc, vah, val`; `previous_poc` доступен при наличии предыдущего профиля; списки зон `hvn, lvn` |
| Зона | `[нижняя граница, верхняя граница]`; профиль должен завершаться на последней закрытой свече |
| `vwap` | `value, source, as_of`; значение на закрытии последней свечи |
| `smart_money` | Список `kind: OB/FVG`, `direction: LONG/SHORT`, `zone`, `created_at`, `confirmed`, `unmitigated`, `source` |
| `cvd` | `source`, `method: aggressor_trades`, `values: [{close_time, value}]`, строго по каждой свече, без сбросов внутри серии |
| `policy.min_atr_ratio` | Явный порог от 0 (не включая) до 1: текущий ATR / среднее предыдущих 20 ATR |
| `news` | `verified`, `source`, `checked_at`, `coverage_start`, `coverage_end`, `events: [{time, impact, relevant}]` |
| `account` | Необязательно: `deposit, deposit_currency, quote_currency, contract_type: linear, contract_multiplier, quantity_step, taker_fee_bps, slippage_bps` |
| `position` | `false` = подтверждённо вне рынка; отсутствие = НЕТ ДАННЫХ; объект = открытая позиция |

Профиль и настоящий CVD поступают от сделок Binance, а не восстанавливаются из
обычных свечных объёмов. OB/FVG выводятся по зафиксированному механическому правилу
из закрытых 15m свечей; движок дополнительно отклоняет повторно посещённые зоны.
История свечей должна покрывать время создания OB/FVG.
Календарь должен быть проверен в последние 15 минут и покрывать следующие 15 минут.
Пустой `events` означает подтверждённое источником отсутствие релевантных событий,
а не разрешение подставить пустой список вместо проверки календаря.

## Точные соглашения стратегии

- Все 7 пунктов обязательны; неизвестные значения запрещают вход.
- Локальные экстремумы: строгие pivot с двумя свечами слева и справа. Последняя свеча —
  sweep относительно последнего подтверждённого pivot. Двусторонний sweep даёт ПРОПУСК.
- Сравниваются CVD на закрытии опорной свечи и sweep-свечи. При равенстве CVD новый
  экстремум CVD отсутствует, поэтому условие дивергенции выполнено согласно заданному правилу.
- Объём sweep строго больше 1.5 × среднее **20 предыдущих** свечей, исключая sweep.
- Цена закрытия должна быть внутри HVN/POC и актуальной OB/FVG того же направления.
- VWAP проверяется по обеим границам рабочей зоны; максимальное расстояние строго < 0.3%.
  Это консервативное уточнение неоднозначного `Zone Price` для зон.
- ATR(14) Wilder рассчитывается из OHLCV. Порог аномально низкого ATR в исходных правилах
  численно не задан, поэтому **обязателен** `policy.min_atr_ratio`.
  Значение 0.5 в синтетическом примере — пример настройки, не универсальный рыночный норматив.
- Entry — закрытие подтверждающей свечи; это расчётный ориентир, не гарантированная цена исполнения.
- SL: минимум sweep − ATR для LONG; максимум sweep + ATR для SHORT.
- TP1: ближайшая граница HVN или VWAP в направлении сделки; TP2: ближайшая граница
  следующего LVN за TP1. При отсутствии целей — ПРОПУСК.
- RR указывается для обеих целей и для позиции 50/50: `(RR1 + RR2) / 2`.
  Минимум 2 применяется к **взвешенному RR**, не только к далёкой второй цели.
  RR показан до издержек; размер позиции включает заданный резерв комиссий и проскальзывания.
- Максимальный расчётный риск — 1% депозита. Размер округляется вниз по `quantity_step`.
  Поддерживаются линейные контракты и депозит в валюте котировки. Инверсные контракты
  и конвертация валют не реализованы. Фактическое проскальзывание может превысить резерв.
- Структура определяется по pivot HH/HL, LH/LL или сжатию диапазона; тренд подтверждается
  VWAP и смещением POC. Неоднозначность обозначается НЕОПРЕДЕЛЁННЫЙ.
- При известной открытой позиции новые входы запрещены; усреднения и мартингейла нет.

## Открытая позиция

Объект `position`:

```json
{
  "direction": "LONG", "entry": 101, "stop_loss": 95,
  "initial_stop_loss": 95, "tp1": 120, "tp2": 145,
  "quantity": 2, "contract_multiplier": 1,
  "tp1_filled": false, "lvn_entry_confirmed": false
}
```

`quantity` — текущий остаток. Закрытие 50% относится к первоначальной позиции;
факт исполнения TP1 передаётся через `tp1_filled`. При достижении SL/TP бот выдаёт
рекомендацию, но не утверждает, что ордер исполнен. PnL валовый, без комиссий/funding.
Подтягивание к POC допускается только при `lvn_entry_confirmed: true`, текущей цене внутри
LVN и уменьшении риска. Расширять исходный стоп запрещено.

Управление выполняется по текущему снимку; полного журнала сделок, сверки биржевых исполнений,
внутрисвечного пути цены и автоматического выявления всех видов инвалидизации пока нет.
Сборщик сделок работает в фоне. Нет проверенного подключения экономического календаря,
распознавания скриншотов, Telegram, подключения ключей биржи или отправки ордеров.
Это локальная версия анализатора,
а не автономный исполнитель сделок.
